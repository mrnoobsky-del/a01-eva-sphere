# A-01 v3.3.0 — Offline Edition: план релиза

## Назначение

v3.3.0 определяет переход от онлайн-зависимого HTML к автономному ядру цифрового двойника. Это документационный и инженерный план, а не заявление о готовности исполняемого offline-файла.

## Целевые артефакты

| Артефакт | Назначение | Критерий готовности |
|---|---|---|
| Single HTML Offline | Открытие двойным щелчком без сети | Полная браузерная приёмка file:// |
| Portable Offline Pack | Переносимый набор ресурсов и документации | Проверка состава архива и запуска |
| PWA / Hosted Offline | Установка и кэширование опубликованной версии | Проверка HTTPS origin и Service Worker |
| Optional Local AI | Локальная языковая модель | Отдельная спецификация runtime, модели и требований к устройству |

## Этапы релиза

1. Baseline и dependency audit исходной версии.
2. Повторяемая сборка JavaScript без внешних runtime imports.
3. Интеграция Three.js и необходимых контролов с соблюдением MIT и сторонних лицензий.
4. Упаковка текстур, моделей, шрифтов, значков, аудио и прочих обязательных ресурсов.
5. Локальная справка, object registry и диагностика.
6. Проверка local storage и JSON export/import.
7. Изоляция сетевых функций в Online Adapter.
8. Offline acceptance на чистом профиле браузера при отключённой сети.
9. Формирование Portable Pack и отдельное документирование PWA.

## Решения, которые считаются обязательными

- Сеть не является условием старта основной 3D-сцены.
- Обязательные библиотеки и ресурсы поставляются внутри HTML или Portable Pack.
- Никаких секретов и приватных API-ключей в клиентском файле.
- Облачный чат Евы не имитируется в offline-режиме.
- Локальные данные не синхронизируются без явного согласия.
- Если браузер не гарантирует долговременное хранение для file://, пользователь получает JSON export/import.
- Необязательные модули могут отключаться без остановки ядра.
- Статические проверки не заменяют визуальную браузерную приёмку.

## Что не входит в v3.3.0 acceptance

- Реальный физический объект Сферы Евы.
- Серверная доступность Cloudflare Worker.
- Полноценная локальная LLM без отдельной установки модели и runtime.
- Автоматическое развертывание на uCoz.
- Гарантия поддержки всех мобильных файловых менеджеров; мобильные платформы тестируются отдельно.

## Текущая точка

Существующая v3.2.2 — online-вариант, который обращается к CDN. Предыдущий local-engine ZIP не принимается как автономный до проверки его фактического состава. Следующий кодовый результат должен иметь воспроизводимый build pipeline и включать доказательства отсутствия обязательных сетевых запросов.

## Инструмент проверки зависимостей

В репозитории добавлен статический анализатор [tools/offline-audit.mjs](../../tools/offline-audit.mjs) и его тест [tests/offline-audit-check.mjs](../../tests/offline-audit-check.mjs). Запуск:

```bash
node tools/offline-audit.mjs path/to/app.html audit-report.json
node tests/offline-audit-check.mjs
```

Для исходной v3.2.2 аудит должен завершаться с FAIL, пока CDN import map и три относительных companion-скрипта не устранены или не встроены. Сетевой вызов Евы фиксируется как online-only endpoint и не должен блокировать локальное ядро.
