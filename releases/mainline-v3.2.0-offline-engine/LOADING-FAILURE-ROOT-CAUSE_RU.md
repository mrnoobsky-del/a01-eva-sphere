# Причина ошибки загрузки локального 3D-движка

В предыдущем комплекте обнаружены два независимых сценария ошибки.

1. В локальном launcher после вызова другого PowerShell-скрипта проверялся `$LASTEXITCODE`. Эта переменная предназначена для кода завершения нативных процессов и не служит надёжным результатом выполнения `.ps1`; из-за этого launcher мог остановиться до запуска локального HTTP-сервера. Исправление: теперь после setup проверяются реальные файлы `three.module.js`, `three.core.js`, `OrbitControls.js` и ревизия Three.js 185.
2. При прямом открытии HTML через `file://` браузер блокирует загрузку ES-модулей. Кроме того, если HTML загрузить на сайт без соседней папки `vendor/three/`, относительные импорты не найдут библиотеки.

## Правильный запуск

- Распаковать весь ZIP в одну папку.
- Запустить `START-A01-OFFLINE.bat`; не открывать HTML двойным щелчком.
- При первом запуске требуется подключение к GitHub Raw для подготовки файлов Three.js r185. Затем движок использует локальную копию.
- При публикации на uCoz загрузить HTML и всю папку `vendor/three/` с сохранением структуры каталогов.

Обработчик ошибки HTML теперь отдельно распознаёт `file://` и показывает исходный текст `error.message`, чтобы не скрывать точную причину.

Статические проверки локальной карты импортов, launcher, режима изучения объектов, пространственной геометрии, синтаксиса ES-модуля и целостности ZIP прошли. Запуск PowerShell на Windows и полный визуальный WebGL walkthrough в этой среде не выполнялись.
