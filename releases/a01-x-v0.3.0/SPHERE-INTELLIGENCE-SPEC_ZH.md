# Sphere Intelligence — 以人为中心的栖居环境工程规范

**A-01 X v0.3.0 · 文档版本 · 2026 年 11 月 22 日**  
**状态：**概念规范与验证计划，不是施工图或楼宇控制器

## 1. 目标

Sphere Intelligence 是帮助伊娃之球提供安全、无障碍和舒适环境的监督系统。Android-01 负责巡检，Human Proxy 合成使用场景评估不同需求。它们是测试工具，而不是系统的中心。

“13 小时”是长期使用和基础设施运行的测试时间窗，包括不同活动、移动、进食、饮水、休息和个人空间。它不代表连续工作 13 小时，也不保证每个人都没有疲劳或压力。目标是减少可避免的负担并提供恢复条件。

## 3. 空间与数据模型

`Sphere → Level → Zone → Room → System → Asset → Sensor/Actuator`

每个对象需要稳定 ID、带单位的几何、用途、相邻区域、运行模式、数据源、单位、时间戳、校准状态和维护负责人。

每个测量值保存：值、单位、传感器位置/高度、时间、数据质量、校准、缺失/错误状态和来源。没有上下文或校准已过期的值不能作为证据。

默认不采集可识别面部、谈话录音、隐蔽生物特征、情绪标签或个人医疗数据。Human Proxy 使用合成场景，而不是诊断。

## 4. 控制层级

- **L0 独立保护：**消防、排烟、疏散、电梯安全回路、电气保护和紧急联锁。Sphere Intelligence 不得替代或绕过。
- **L1 本地控制器/BMS：**在工程限值和制造商保护范围内运行经批准的逻辑。
- **L2 Sphere Intelligence：**观察、预测、比较并提出建议。先使用只读/影子模式；未来仅通过批准的网关发送有限、可审计的命令。
- **L3 人：**操作员批准关键更改；使用者可以在安全范围内调整个人照明、温度和隐私偏好。
- **L4 学习：**离线分析历史数据和仿真。新策略需通过回归、故障和网络安全测试，并经人工批准。

AI 不直接控制消防、疏散、电梯安全回路、医疗决策或应急电源。

## 5. 工程规则

- CO₂ 不是完整空气质量指标；还要考虑室外空气量、污染源、风量、过滤、排风和维护。
- 不应为了舒适而主动改变普通居住穹顶的整体大气压力。房间压差只用于经过设计的气流方向控制。
- 大型中庭要考虑垂直热分层、玻璃屋顶太阳得热、辐射表面、遮阳和局部气流。
- 照明结合日光、任务照明、眩光控制和夜间模式；紫色装饰灯不能替代正常照明。
- 声学应检查峰值、频谱、混响和语音隐私；不录音。
- 电梯是主要无障碍垂直交通；自动扶梯仅作补充；楼梯属于独立疏散设计。
- 饮用水、技术水、灰水和黑水应按工程设计分流；卫生间和淋浴需排风、湿度和清洁策略；水培区应有独立气候。
- 不通过面部、语音或步态推断心理状态；提供清晰导航、休息和独处选择。
- 备用能源和持续运行时间必须由负载、容量、燃料、通风和测试程序计算证明。

## 6. 仿真工具候选

EnergyPlus/OpenStudio 用于能源和热环境仿真；Radiance 用于日光和照明；必要时使用经验证的 CFD 研究复杂气流；Recast Navigation 研究可通行性和路径，电梯作为显式跨层连接；声学模型需与现场测量结合；IFC 和 IDS 用于建筑信息交换与机器可检查的要求。

EnergyPlus Runtime API 可以在运行中的**仿真**内读取传感器值和设置执行器变量，不代表它可以直接控制真实建筑设备。

## 7. 验证阶段

G0 几何与单位确认 → G1 区域需求 → G2 工程模型与不确定性 → G3 正常/峰值/故障仿真 → G4 控制器模拟器 HIL → G5 校准和现场调试 → G6 人工批准的影子/有限运行 → G7 持续维护与复验。
