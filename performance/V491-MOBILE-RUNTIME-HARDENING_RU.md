# A-01 v4.9.1 — мобильная производительность и приёмка

**Дата:** 27 ноября 2026 года  
**Основа:** GitHub main / A-01 v4.9.0  
**Тип:** изолированный preview, основная ветка и главная страница не изменяются.

## Изменения в runtime

1. Пересчёт LOD для всех долек выполняется не чаще одного раза в 125 мс на телефонах и 75 мс на desktop вместо каждого отрисованного кадра. Принудительное обновление остаётся при выборе объекта.
2. Проверка взгляда и raycast в режиме прогулки ограничены интервалом 220 мс на телефонах; desktop сохраняет 125 мс.
3. Направление взгляда использует повторно используемый THREE.Vector3, а не создаёт новый объект на каждом raycast.
4. Сохранены 60 FPS как целевая частота непрерывного рендеринга, demand-driven render, адаптивный pixel ratio, batching, feature picking, LOD и обработка восстановления WebGL.
5. Сохранена отрисовка неактивной вкладки на паузе, а не постоянный фоновый render loop.

## Мобильная оболочка

Отдельная страница формирует компактный режим: навигация по разделам сверху, 3D-сцена на доступную высоту, контекстная панель снизу, быстрые действия поиска и прогулки. Она загружает оптимизированный v4.9.1 runtime в iframe того же Wix origin.

## Встроенный 60-секундный бенчмарк

Кнопка «Замер 60 с»:
- 15 секунд прогрева;
- 60 секунд измерения в одинаковом сценарии с медленным автоматическим вращением камеры;
- измеряет интервалы между фактическими вызовами renderer.render(), p50/p95/p99, число интервалов выше 16.67 и 33.3 мс, CPU-время отправки команд, draw calls и triangles;
- собирает браузер, размер viewport, число ядер, доступную оценку памяти и DPR;
- восстанавливает режим вращения и положение камеры после замера;
- выдаёт копируемый JSON.

CPU-время вызова renderer.render не является прямым GPU-time; интервалы вызовов не являются подтверждённым presentation-time экрана. Для приёмки нужны три одинаковых прогона на desktop и на реальном телефоне.

## Статус проверки

Статическая проверка должна подтвердить синтаксис встроенного JavaScript, уникальность постоянных HTML ID, версии/SEO metadata, наличие мобильных ограничителей и сохранение основных API/функций сцены.

**Не заявляется:** достижение 60 FPS на всех устройствах. Реальное браузерное/WebGL тестирование и визуальная приёмка на физических Android/iOS устройствах остаются обязательными. Среда разработки не имеет доступного браузерного прогона в этой сессии; поэтому никаких фактических FPS здесь не приписывается.
