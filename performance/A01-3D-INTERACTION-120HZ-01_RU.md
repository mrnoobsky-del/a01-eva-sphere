# A-01 — стандарт исследования 3D-сцены, 120 Hz и свободного обзора
**Документ:** A01-3D-INTERACTION-120HZ-01  
**Версия:** 1.0  
**Дата:** 27 ноября 2026 года  
**Статус:** обязательная проектная спецификация; реализация и аппаратная приёмка ещё не подтверждены.

## 1. Цель

Цифровая Сфера должна оставаться главным объектом внимания. Пользователь самостоятельно управляет камерой и исследует пространство, а интерфейс предоставляет инструменты, не заслоняя сцену.

Стандарт распространяется на сферу целиком, этажи, дольки, помещения, роботов, инженерные узлы и любые другие объекты, которые можно выбрать и изучить.

## 2. Частота кадров: 120 Hz как целевой режим

120 FPS — целевой режим на устройствах, где экран, браузер, GPU и CPU способны его устойчиво поддерживать. Это не безусловная гарантия для любого устройства.

| Режим | Бюджет кадра | Поведение |
|---|---:|---|
| 120 Hz | 8,33 мс | приоритетный режим на совместимом оборудовании |
| 90 Hz | 11,11 мс | адаптация к доступной частоте экрана |
| 60 Hz | 16,67 мс | базовый режим совместимости |
| Ниже 60 Hz | по факту устройства | сохранение управляемости и адаптивное качество |

### Правила реализации
- Использовать `requestAnimationFrame` и фактический временной шаг; не запускать независимый цикл с фиксированной частотой, который конкурирует с браузером.
- Не ограничивать исследование жёстким потолком 60 FPS.
- Неподвижная сцена остаётся demand-driven: кадр запрашивается при изменении камеры, объекта, интерфейса или состояния.
- Во время активного жеста камера обновляется в пределах возможностей дисплея и устройства.
- При потере производительности сначала измерять CPU/GPU bottleneck; адаптивное качество применять постепенно и обратимо.
- Не снижать постоянно геометрию, качество материалов, текстур или теней без измерений и визуальной приёмки.
- Учитывать `devicePixelRatio`, системную частоту экрана, вкладку в фоне, `prefers-reduced-motion` и энергосбережение.
- Не путать частоту обновления экрана, частоту вызовов `requestAnimationFrame` и фактически отрисованные кадры.

### Метрики
В каждом прогоне записывать frame time p50/p95/p99, dropped/long frames, CPU main-thread time, GPU time (если доступно), draw calls, triangles, texture/geometry counts, pixel ratio и WebGL errors.

Целевые ориентиры для 120 Hz:
- p95 frame time ≤ 8,33 мс;
- p99 frame time ≤ 16,67 мс;
- три одинаковых прогона по 60 секунд после 15 секунд прогрева;
- отдельно измерять idle, вращение камеры, touch-жесты, выбор объекта, прогулку и открытие карточки.

Если целевые значения не достигаются, публиковать фактические результаты и ограничения тестового устройства, а не писать «120 FPS поддерживается».

## 3. Полное отсутствие самопроизвольного вращения

По умолчанию:
- `OrbitControls.autoRotate = false`;
- `enableDamping = false` для режима точного исследования, если тесты не докажут, что короткая управляемая инерция полезна и не вызывает самодвижения;
- автоматическое вращение модели выключено;
- демонстрационные вращения и туры не запускаются сами после загрузки;
- камера не продолжает движение после отпускания мыши или пальца;
- фоновые анимации не должны имитировать движение самой Сферы.

Любое автоматическое движение допустимо только как явно запущенный пользователем отдельный сценарий с заметной кнопкой остановки. При ручном захвате камеры такой сценарий немедленно уступает управление человеку.

После `pointerup`, `pointercancel`, потери фокуса окна или скрытия вкладки состояние ввода сбрасывается. Не допускаются залипшие pointer-состояния и остаточное движение.

## 4. Исследование объекта без перекрытий

### Основной принцип
Выбранный объект и существенная часть окружающей геометрии всегда остаются видимыми. Информационная панель не должна закрывать объект, который пользователь пришёл изучить.

### Desktop
- При входе в режим исследования использовать отдельную компоновку.
- Временно скрывать обычную навигацию, второстепенные панели, служебные метки и элементы, не нужные для изучения.
- Карточка объекта размещается в свободной области рядом с объектом, а не поверх его геометрии.
- Камера кадрирует объект с безопасными полями; учитывать габариты объекта и его bounding box.
- Если рядом нет свободного места, карточка перемещается в боковую колонку, а не накладывается на объект.
- Не допускать, чтобы карточка сжимала сцену настолько, что объект становится слишком мал.

### Mobile
- Использовать нижнюю компактную карточку или выдвижную панель.
- Карточка не должна перекрывать выбранный объект; камера может аккуратно перекомпоновать кадр с учётом высоты панели.
- Свайпы по карточке не должны вращать сцену.
- Должна быть доступна кнопка свернуть/развернуть сведения.
- Важные действия доступны одной рукой и имеют достаточные сенсорные области.

### Все устройства
- В режиме исследования убрать не относящиеся к объекту всплывающие подсказки и HUD.
- Подсветка выбранного объекта не должна скрывать материалы или детали.
- При открытии информации не менять выбранный объект без явного действия пользователя.
- При закрытии карточки восстановить прежний контекст и ракурс, если пользователь сам не изменил камеру.
- Клавиша Escape закрывает карточку/режим исследования; клавиатурная навигация и доступные подписи сохраняются.

## 5. Управление камерой

- Мышь: drag для вращения, колесо для зума, понятный reset-view.
- Сенсор: один палец — вращение; pinch — масштаб; жест по панели — прокрутка панели.
- Клавиатура: поддерживаемые действия имеют видимые подсказки и не конфликтуют с навигацией страницы.
- Ограничить минимальную и максимальную дистанцию, не допускать прохода камеры сквозь геометрию.
- Переход к объекту должен быть коротким и прерываемым пользователем.
- После ручного управления камера не должна самопроизвольно возвращаться к исходной позиции.

## 6. Архитектурное разделение

Режимы должны быть явными состояниями интерфейса:
1. **Общий обзор** — свободная сцена и компактная навигация.
2. **Исследование объекта** — объект в фокусе, второстепенный UI скрыт, карточка не перекрывает геометрию.
3. **План/этаж** — навигация по этажам и зонам без случайного вращения сцены.
4. **Прогулка** — управление перемещением; орбитальные жесты не конфликтуют с ходьбой.
5. **Демонстрация** — отдельный сценарий, только по явному запуску и с доступной остановкой.

Каждый переход обязан корректно завершать предыдущие pointer, camera-flight, animation и selection состояния.

## 7. Приёмочные проверки

| ID | Проверка | Критерий |
|---|---|---|
| INT-01 | Первичная загрузка | камера и модель неподвижны |
| INT-02 | Idle 60 секунд | отсутствует самопроизвольное вращение |
| INT-03 | Drag мышью | движение только при удержании; прекращается при отпускании |
| INT-04 | Touch orbit | вращение прекращается после отпускания |
| INT-05 | Pointer cancel | нет залипшего ввода |
| INT-06 | Выбор объекта | выбранный объект остаётся видимым |
| INT-07 | Карточка desktop | не перекрывает объект и не делает его чрезмерно малым |
| INT-08 | Карточка mobile | панель не закрывает объект; pinch и scroll не конфликтуют |
| INT-09 | Закрытие исследования | возвращается контекст и ожидаемый ракурс |
| INT-10 | Потеря/возврат фокуса | нет остаточного вращения; сцена корректно перерисовывается |
| INT-11 | 120 Hz monitor | измерены p50/p95/p99 и фактический frame rate |
| INT-12 | 60 Hz fallback | интерфейс остаётся отзывчивым |
| INT-13 | Reduced motion | не запускаются декоративные автодвижения |
| INT-14 | Resize/orientation | сцена и панели пересчитываются без перекрытий |

Проверить desktop минимум на 120 Hz и 60 Hz дисплеях, а mobile — минимум на одном среднем и одном производительном устройстве. Для каждого профиля — три повторяемых прогона.

## 8. Порядок внедрения

1. Зафиксировать точный HTML, commit SHA, браузер, устройство и текущие параметры рендеринга.
2. Проверить все циклы `requestAnimationFrame`, OrbitControls listeners, тестовое вращение, cameraFlight и режим исследования.
3. Устранить самодвижение и залипшие pointer-состояния.
4. Реализовать responsive layout режима исследования и проверку пересечения карточки с проекцией объекта.
5. Перевести frame pacing на адаптацию к возможностям дисплея без жёсткого ограничения 60 Hz.
6. Снять baseline и after-measurements; сравнить визуальные контрольные кадры.
7. Провести ручную проверку мыши, touch, клавиатуры, Escape, pointercancel, resize и WebGL recovery.
8. Только после этого обновлять номер версии и считать стандарт реализованным.
