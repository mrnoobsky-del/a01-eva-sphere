# A-01 Performance — плавность и 60 FPS без потери качества

**Дата актуализации:** 27 ноября 2026 года  
**Текущая основная сборка:** A-01 v4.9.0  
**Статус:** исходник проверен статически; браузерные замеры и подтверждение 60 FPS ещё не выполнены.

## Текущая база

Основная сборка GitHub main — [A-01 v4.9.0](../digital-twin/README_RU_v490.md), использует Three.js 0.185.0. В ней сохранены batching, LOD и нативная адаптивная настройка pixel ratio. Неподвижная сцена рендерится по запросу; активные анимации ограничены интервалом не чаще 60 Гц.

**Важно:** ограничение 60 Гц не означает, что браузер реально выдаёт 60 FPS. Необходимы воспроизводимые измерения на конкретных устройствах.

## Цель и критерии

Цель — устойчивые 60 кадров/с на согласованных эталонных desktop и mobile конфигурациях при сохранении визуального качества.

| Метрика | Целевой критерий |
|---|---:|
| Бюджет кадра | 16,67 мс |
| p95 времени кадра | ≤ 16,67 мс |
| p99 времени кадра | ≤ 33,3 мс |
| Повторяемость | 3 одинаковых прогона |
| Визуальное качество | без непредусмотренного ухудшения |

Это критерии приёмки, а не уже полученные результаты.

## Приоритетный порядок работ

1. Зафиксировать точный HTML-файл, commit SHA, браузер, ОС, CPU/GPU, viewport и DPR.
2. Снять 60-секундный baseline после 15 секунд прогрева; повторить трижды.
3. Записать p50/p95/p99 frame time, long tasks, draw calls, triangles, загрузку ресурсов и ошибки WebGL.
4. Отдельно измерить начальный обзор, вращение камеры, прогулку, смену этажей, тяжёлые панели и активные анимации.
5. Исправлять только доказанное узкое место. Сохранять визуальные контрольные кадры до/после.
6. Повторить измерения на desktop и mobile.

## Аудит ручного вращения

В исходнике v4.9.0 статически подтверждены `enableDamping = false` и `autoRotate = false` при начальной настройке. Модельное тестовое вращение также выключено по умолчанию и включается отдельной кнопкой.

В тестовой копии добавлено отслеживание событий OrbitControls start/end: ручное вращение проходит через общий 60 Гц frame pacing, а ручной захват камеры останавливает демонстрационное авто-вращение. Это проверяемая гипотеза оптимизации. До браузерной проверки нельзя заявлять, что лаг устранён.

## Ограничения качества

Не снижать постоянно разрешение, не отключать все тени и не удалять архитектурные детали только ради красивого числа FPS. Сначала измерить CPU/GPU и проверить batching, LOD, повторное использование ресурсов, raycasting и стоимость материалов/текстур.

Не смешивать время первоначальной загрузки с устойчивой производительностью кадра. Не выдавать ограничитель 60 Гц за доказательство 60 FPS.
