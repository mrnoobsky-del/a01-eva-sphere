# A-01 — мост геометрии купола с EnergyPlus

**Версия:** 0.1.0 / пакет проекта A-01 v3.7.9  
**Состояние:** экспериментальный расчётный прототип; физическая модель не утверждена.

## Что делает приложение

Приложение читает канонический набор параметров geometry/a01-shell-parameters-v0.1.json, создаёт замкнутую триангулированную оболочку и записывает её в IDF для EnergyPlus 26.1.0. Сам расчёт выполняет EnergyPlus engine, скомпилированный в WebAssembly и загружаемый браузерным приложением через @idfkit/engine.

12 родительских секторов и 144 кандидата кассет сохраняются как идентификация исходной оболочки. Это не 12 или 144 самостоятельные тепловые зоны.

## Запуск

Нужен Node.js и npm.

    cd tools/a01-energyplus
    npm install
    npm run dev

Vite откроет локальную страницу на http://127.0.0.1:4179.

Проверка геометрии и production-сборка:

    npm test
    npm run build
    npm run preview

Скрипты predev и prebuild автоматически подготавливают EnergyPlus WASM assets, схемы EnergyPlus и исходный JSON геометрии в локальной папке public/.

## Входные параметры

Перед экспортом IDF и запуском расчёта интерфейс требует:

1. **Диаметр опорного кольца в метрах.** Фактический проектный размер, измеренный по тому контуру, который в модели принят нижней границей оболочки. Он не назначается автоматически.
2. **U оболочки, Вт/(м²·К).** Совокупное расчётное значение конструкции. Материал в этой первой модели задаётся как слой без тепловой массы с сопротивлением R = 1/U.
3. **Солнечное поглощение оболочки.** Значение 0–1 из спецификации наружной поверхности.
4. **EPW.** Почасовой погодный файл; координаты площадки и высота берутся из его строки LOCATION.

Уставки 20 °C / 26 °C — редактируемые начальные сценарные значения, не утверждённые требования проекта. Инфильтрация и наружный воздухообмен по умолчанию равны нулю, то есть не включаются в расчёт, пока пользователь явно не задаст их в ACH.

## Преобразование геометрии

Исходная поверхность описана эллипсоидальными параметрами в модельных единицах, Y направлена вверх. EnergyPlus-модель использует Z как вертикальную ось.

Масштаб определяется как k = D_ring / (2 a sin(theta_rim)), где a = baseRadius × scaleXZ, b = baseRadius × scaleY, theta_rim = pi × thetaEndPiFactor. Координаты оболочки переносятся с Y-up на Z-up, нижняя отметка назначается Z = 0.

В расчётную поверхность намеренно не переносится визуальный радиальный множитель panelRadialFactor = 1.006; смещение centerY также не трактуется как строительная величина. Верхняя маленькая графическая усечённая область закрывается веером треугольников к математической вершине. Основание строится с тем же количеством граничных узлов, что и нижний край сетки оболочки.

## Текущая EnergyPlus-модель

- Одна воздушная зона: A01_DOME_VOLUME.
- Наружная оболочка: треугольные BuildingSurface:Detailed поверхности с наружной границей Outdoors.
- Основание: одна адиабатическая поверхность A01_DOME_BASE.
- Термостат с редактируемыми уставками.
- ZoneHVAC:IdealLoadsAirSystem — расчёт идеальной потребности зоны в тепле/холоде, не модель конкретного оборудования.
- Опциональная инфильтрация и естественный наружный воздухообмен по введённым ACH.
- Почасовые переменные температуры зоны и энергии Ideal Loads.
- EPW годовой период; шаг расчёта — 4 шага в час.

## Что пока не моделируется

Внутренние перекрытия и этажи, отдельные помещения, атриумные перегородки, остекление/двери/тамбуры, затенение здания, тепловые мосты, физические слои и тепловая масса оболочки, люди, освещение, оборудование, кухни, серверная, ГВС, почасовые расписания, реальные приточно-вытяжные установки, рекуперация и характеристики тепловых насосов. Не моделируются CFD, давление оболочки, конденсация, обледенение, дымозащита и пожарные сценарии.

Адиабатическое основание — вычислительное замыкание первой зоны, а не проект пола по грунту. Ideal Loads — расчёт нагрузки при заданных уставках, а не подбор мощности, модели котельной/теплового насоса или электропотребления всего комплекса.

## Проверка и статус

Геометрические unit-тесты проверяют:
- сохранение параметров и идентификаторов 12/144;
- масштабирование длин, площадей и объёма;
- отсутствие вырожденных треугольников;
- совпадение всех нижних узлов оболочки с узлами основания при разных разрешениях сетки.

Наличие исходного кода и тестов не означает, что сборка, запуск WebAssembly или симуляция на реальном EPW уже выполнены. Перед использованием результатов необходимо выполнить npm test, npm run build, затем настоящий прогон EnergyPlus на площадочном EPW и проверку .err/AllSummary квалифицированным инженером.

## Лицензии

Используются пакеты idfkit и EnergyPlus Engine Assets. Условия лицензирования каждого пакета и EnergyPlus следует проверять по их собственным опубликованным лицензиям. Не распространяйте собранные бинарные файлы без соблюдения соответствующих условий и уведомлений.
