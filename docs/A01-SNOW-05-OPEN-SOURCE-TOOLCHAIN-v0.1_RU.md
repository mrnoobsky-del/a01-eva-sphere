# A01-SNOW-05 — Исследование готовых open-source решений для EVA SnowFlow

**Редакция:** 0.1 · **Дата проверки:** 28 ноября 2026 года  
**Статус:** первичный аудит репозиториев; код не интегрирован

## 1. Вывод

Полного готового решения «скосы + подогрев дорожного покрытия + распознавание льда + снегосбор + водоотвод + безопасное управление» среди проверенных репозиториев не найдено. Реалистичный путь — заимствовать проверяемые идеи и отдельные программные компоненты, а механическую геометрию, тепловой расчёт, дренаж и безопасную интеграцию разработать для A-01 отдельно.

Публичный репозиторий или наличие исходников не означает разрешение на копирование, переработку или коммерческое использование. До использования кода нужно проверить действующую лицензию конкретной версии, зависимости, аппаратные схемы и обязанности по атрибуции/распространению.

## 2. Кандидаты

### 2.1 SmartRoadMonitor — датчики и классификация покрытия

Репозиторий: https://github.com/sandipbohara1/SmartRoadMonitor

README описывает end-to-end IoT систему мониторинга состояния дороги, в том числе лёд, снег и сухой асфальт; архитектура включает узел датчиков, LoRa, ASP.NET Core API, базу SQL Server, dashboard и карту риска. В списке аппаратуры указаны MLX90614 для температуры поверхности, DHT22 для температуры/влажности воздуха, спектральный датчик AS7343 и модуль LoRa. В описании встречается обозначение Raspberry Pi Pico W/Pico 2 W; точную плату и версию BOM нужно подтвердить по исходникам.

**Применение в A-01:** прототипная архитектура датчика, передача телеметрии, хранение наблюдений и карта состояния зон.

**Ограничения:** небольшой исследовательский репозиторий; показатели точности и отказоустойчивости не являются независимой сертификацией. Спектральная классификация требует испытаний на прозрачном льду, мокром снеге, загрязнённой поверхности, реагентах и разном освещении. В просмотренной навигации репозитория отдельный файл лицензии не обнаружен; не копировать исходники и не включать их в продукт до подтверждения лицензии/разрешения.

### 2.2 FHC-PWM — зональный контроллер отопления

Репозиторий: https://github.com/jnasholm/fhc-pwm

Проект описывает контроллер ESP32/ESPHome для гидравлического тёплого пола: зоны с термостатами, PID, модулированные исполнительные приводы и твердотельные реле. В GitHub указана лицензия GPL-3.0.

**Применение в A-01:** изучить разбиение на зоны, контроль уставок, PWM-управление приводами, структуру конфигурации и телеметрию.

**Ограничения:** домашний тёплый пол — не наружная дорожная система. В нём нет готового проекта для снеговой нагрузки, дренажа, обледенения, уличной электробезопасности и экстремальной погоды. Использование производного кода требует отдельной GPL-3.0 совместимости и юридической проверки.

### 2.3 OpenHydronic — локальная защитная логика ESP32

Репозиторий: https://github.com/davdlic/OpenHydronic

README описывает ESP32/ESPHome-контроллер зон гидравлического отопления, локальный safety engine, безопасное состояние при включении питания, защиту насоса, ограничения циклов, аварийную остановку и автономную работу при потере Home Assistant/сети. В GitHub указана GPL-3.0.

**Применение в A-01:** изучить принципы fail-safe, локальную автономность, watchdog, блокировки насоса и независимость защитной логики от удалённого сервера.

**Ограничения:** проект ориентирован на домашнюю отопительную систему. Его схема не является сертифицированной дорожной автоматикой; электрические и исполнительные решения нельзя копировать без отдельной оценки. Не использовать ESP32 как единственный safety-контроллер критической установки. Требуется GPL-3.0 проверка для производного кода.

### 2.4 SnowByte RC Snowplow — механическая уборка

Репозиторий: https://github.com/cele9999/RCSnowplow

Проект содержит код Arduino, 3D-печатаемые детали и инструкции для небольшого радиоуправляемого снегоуборщика SnowByte.

**Применение в A-01:** концепция малого испытательного робота, механика отвала, ремонтопригодность и взаимодействие с поверхностью.

**Ограничения:** это небольшой RC-аппарат, а не автономная машина для общественной дороги. В репозитории указана CC BY-NC-SA 4.0 — некоммерческое использование и ShareAlike. Не переносить его код/модели в коммерческий компонент без разрешения правообладателя и проверки условий лицензии.

### 2.5 NCAR Parallel SnowModel — переносимый ветром снег

Репозиторий: https://github.com/NCAR/Parallel-SnowModel

Научная реализация параллельной версии распределённой модели SnowModel, включающей атмосферные и снежные процессы и модуль SnowTran-3D. README предупреждает, что репозиторий дополняет оригинальный SnowModel, не содержит всех необходимых предварительных операций, а некоторые функции не параллелизированы или недостаточно проверены.

**Применение в A-01:** исследовать крупномасштабный снежный перенос, влияние рельефа/ветра и сценарии формирования заносов при наличии корректных метеоданных и компетенции моделирования.

**Ограничения:** научный код не является CFD-моделью микрорельефа плитки и не рассчитывает сцепление шин/пешеходов. Лицензию следует проверить до копирования/модификации; до этого использовать публикации, описание метода и собственную реализацию только в пределах юридически разрешённого использования.

## 3. Инженерные источники вне GitHub

- [ASHRAE Handbook Chapter 52](https://handbook.ashrae.org/handbooks/A23/IP/a23_ch52/a23_ch52_ip.aspx) — основной открытый справочный материал по снеготаянию: тепловой баланс, плита, гидравлика, управление и защита от замерзания.
- [FHWA — How Do Snow Fences Work?](https://ops.fhwa.dot.gov/weather/resources/publications/tech_briefs/snowfence.htm) — принцип контролируемого накопления переносимого ветром снега.
- [FHWA — Snow Drifting near Barriers](https://www.fhwa.dot.gov/ENVIRONMENT/noise/noise_barriers/design_construction/design/design12.cfm) — необходимость оценивать новые зоны заносов, создаваемые барьерами.

## 4. Рекомендованный технологический стек A-01

| Функция | Предпочтительная линия исследования | Не принимать пока |
|---|---|---|
| Датчики покрытия | Температура + осадки/влага + независимое подтверждение состояния | Один спектральный сенсор как единственную защиту |
| Передача телеметрии | Проводной интерфейс на критическом оборудовании; LoRa/сеть для разнесённых датчиков после анализа | Публичный Wi-Fi как safety-канал |
| Локальная автоматика | Отдельный промышленный контроллер/PLC с аппаратными защитами | Только ESP32 без независимых interlocks |
| Зональное управление | Идеи из FHC-PWM и OpenHydronic после лицензии и адаптации | Прямое копирование схем домашнего отопления |
| Цифровой мониторинг | Eva/Orion как диспетчеризация и журнал | AI как safety PLC |
| Снежный перенос | Сайт-специфическая модель и тесты, NCAR SnowModel как возможная научная основа | Применять региональную модель к форме канавки без валидации |
| Механическая уборка | Сменный тестовый отвал/робот с ручным управлением | Неквалифицированный автономный робот среди людей |

## 5. План интеграции без нарушения лицензий

1. Сохранить ссылки и дату проверки в реестре внешних технологий.
2. Получить лицензию, NOTICE, список зависимостей и точные версии каждого кандидата.
3. Разделить «изучение принципа», «совместимую библиотеку», «производный код» и «независимую реализацию».
4. Создать собственную схему требований и интерфейсов A-01, не копируя недоказанные схемы.
5. Прототипировать телеметрию на отдельном стенде.
6. Проверить точность сенсоров независимым эталонным оборудованием.
7. Подключать только к тестовой имитации исполнительных механизмов до прохождения анализа отказов и инженерной экспертизы.
