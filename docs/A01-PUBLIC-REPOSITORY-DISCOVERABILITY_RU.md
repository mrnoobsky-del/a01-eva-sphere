## 1. Факт существования

Проверка GitHub REST API на 27.11.2026 вернула:
- `full_name`: `mrnoobsky-del/a01-eva-sphere`;
- `private`: `false`;
- `visibility`: `public`;
- `default_branch`: `main`;
- `archived`: `false`;
- `created_at`: `2026-11-12`.

Следовательно, репозиторий существует и является публичным. Прямая ссылка открывает GitHub-репозиторий. Ответ стороннего AI-сервиса «такого проекта нет» не опровергает этот факт.

## 2. Что удалось и не удалось подтвердить в поиске

На момент проверки запросы по точному имени репозитория и домену GitHub не вернули соответствующую страницу в доступных веб-результатах. Это означает только, что использованный поиск не показал результат; это не доказательство, что URL отсутствует во всех индексах Google или что он никогда не появится.

Google указывает три базовых технических условия eligibility: Googlebot может получить URL, сервер возвращает HTTP 200 и содержание индексируемо. Даже выполнение этих условий не гарантирует индексацию. Для AI Overviews / AI Mode Google также указывает, что страница должна быть индексирована и допущена к показу в Search; специальных дополнительных требований для AI Overview нет.

- Google Search technical requirements: https://developers.google.com/search/docs/essentials/technical
- AI Features and Your Website: https://developers.google.com/search/docs/appearance/ai-features
- Page indexing report: https://support.google.com/webmasters/answer/7440203

Это вероятные факторы обнаружимости, не доказанная причина конкретного ответа Google AI.

## 5. Что требует действия владельца GitHub

В этой среде нет доступного действия для изменения настроек репозитория, поэтому следующие шаги оставлены владельцу:
1. В GitHub → Settings → General → Social preview — добавить собственный social-preview image с названием A-01.
2. В About — поставить более содержательное описание, например: `Open documentation and digital twin for A-01, the human-centred Sphere of Eva concept: modular architecture, energy, engineering, accessibility and AI-assisted services.`
3. Добавить релевантные GitHub Topics: `open-source`, `digital-twin`, `architecture`, `sustainable-building`, `modular-construction`, `building-systems`, `threejs`, `human-centered-design`.
4. Указать официальный сайт проекта в поле Website, если он ведёт на актуальную публичную страницу с понятной ссылкой обратно на репозиторий.
5. Проверить Settings → Pages. Если Pages включены, опубликовать документационный сайт из согласованной ветки и добавить sitemap. Если Pages не настроены, не заявлять, что GitHub Pages уже работает.
6. Для собственного домена/поддомена подтвердить владение в Google Search Console, проверить HTTP 200, robots.txt, canonical и sitemap; отправить URL на проверку индексации. Нельзя подтверждать весь домен github.com от имени владельца одного репозитория.

## 6. Что нельзя обещать

Ни sitemap, ни README, ни GitHub Topics, ни заявка на переобход не гарантируют индексацию или попадание в AI-ответы. Google сам подчёркивает, что техническая eligibility не равна фактическому включению в индекс или выдачу. После публикации нужно повторно проверить точный URL в обычном Google Search и Search Console, а не считать проблему решённой только потому, что GitHub отдаёт страницу.
