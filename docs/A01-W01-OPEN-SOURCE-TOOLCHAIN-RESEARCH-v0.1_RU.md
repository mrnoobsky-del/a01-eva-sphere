# A01-W01-OPEN-SOURCE-TOOLCHAIN-RESEARCH-01 — готовые GitHub-инструменты для W-01

**Редакция:** 0.1  
**Дата исследования:** 26 ноября 2026 года  
**Объект:** A01-L00-D04 / W-01 — санитарный модуль  
**Статус:** исследование внешних репозиториев; ничего из перечисленного пока не внедрено в цифровой двойник A-01 и не принято как инженерный расчёт.

## 1. Краткий результат

Одного готового GitHub-проекта, который одновременно решает геометрию нашего секторного помещения, корректную расстановку сантехники, доступность, российские инженерные расчёты, BIM/IFC и браузерную визуализацию, не найдено.

Рациональнее собрать проверяемую связку по задачам:

1. **Геометрия и реальные сантехнические модели:** FreeCAD + выборочные модели из FreeCAD-library.
2. **Предварительная компоновка и MEP-исследование:** openBIMstudio как отдельная тестовая среда, а не как источник готового проекта.
3. **Авторитетная модель и обмен:** Bonsai / IfcOpenShell с IFC и IDS.
4. **Браузерный IFC-просмотр:** ThatOpen Engine Components — отдельный просмотрщик/инструмент измерений, который можно позднее интегрировать в A-01.
5. **Zamodelka:** изучать как русскоязычный пример flow-first MEP-интерфейса, но не переносить код, пока не появится явная лицензия или разрешение автора.

Текущую сборку A-01 v4.9.0 не следует заменять одной из этих систем целиком. Сначала нужен отдельный маленький W-01 proof-of-concept с проверяемым обменом файлами.

## 3. Что именно можно взять из openBIMstudio

Основной репозиторий: https://github.com/amdghedy/openBIMstudio

### 3.1 Сантехнические семейства

Папка: [Plumbing Fixtures](https://github.com/amdghedy/openBIMstudio/tree/main/public/families/Plumbing%20Fixtures).

Обнаружены JSON-семейства:
- настенный WC;
- напольный WC;
- пьедестальная и столешничная раковины;
- писсуар;
- уборочная раковина;
- ванна и душевой поддон.

Например, [wall-hung-toilet.json](https://github.com/amdghedy/openBIMstudio/blob/main/public/families/Plumbing%20Fixtures/wall-hung-toilet.json) содержит параметрические поля width/depth/height, elevation, connectionSize и вычисляемый footprint. IFC-класс обозначен как IfcSanitaryTerminal.

**Важная оговорка:** текущая геометрия этих seed-family — примитив box, то есть габаритный заместитель, а не детальная форма унитаза или раковины. Для ранней расстановки блоков и оценки занимаемого объёма это удобно; для реалистичной 3D-модели нужно заменить семейства на CAD-модели или собственные проверенные геометрии.

### 3.2 Водоснабжение и канализация

В коде есть:
- src/modules/mep/plumbing.ts — предварительная оценка пикового расхода по Hunter/WSFU и оценка гидроудара по Joukowsky;
- src/modules/mep/drainage.ts — таблицы DFU и предварительный выбор канализационных размеров/уклонов;
- src/modules/mep/pressure.ts — потери давления по Darcy–Weisbach, Colebrook–White и местные сопротивления;
- src/modules/mep/sizing.ts и sizing-methods.ts — подбор сечений по расчётному расходу и скорости;
- src/modules/mep/router.ts — 3D-маршрутизация с препятствиями и путевыми точками;
- src/modules/mep/connectivity.ts, connectors.ts, network.ts — связи сегментов, фитингов и приборов, диагностика сети.

Это даёт полезный предметный материал для исследования трасс ХВС/ГВС/канализации, но не готовые параметры для W-01.

### 3.3 Что авторы сами называют ограничениями

Источник: [MEP Engine Capabilities](https://github.com/amdghedy/openBIMstudio/blob/main/docs/engineering/MEP_ENGINE_CAPABILITIES.md).

В документе авторы прямо указывают:
- MEP имеет статус limited;
- отсутствует подтверждение соответствия принятому строительному кодексу;
- только одна расчётная область (трение в воздуховоде) сопоставлена с опубликованными точками ASHRAE; остальные MEP-области имеют unit tests, но не независимую валидацию;
- сантехнический drainage-модуль опирается на IPC DFU-таблицы и описан как foundation-level, а не verified design workflow;
- методики не являются региональными российскими расчётами.

**Вывод:** openBIMstudio можно применять для учебной/предпроектной проверки логики, трассировки и чувствительности параметров. Нельзя переносить его DFU, Hunter, диаметры или уклоны в A-01 как готовое соответствие СП 30.13330.2020.

Лицензия основного репозитория — MIT. При адаптации кода сохранять лицензионное уведомление и проверять лицензии зависимостей.

README библиотеки указывает CC-BY 3.0 и требует атрибуции авторов моделей. Авторство каждой конкретной детали необходимо подтвердить по её свойствам/истории Git до включения в публичный репозиторий A-01. Не скачивать всю библиотеку: выбрать только нужные детали.

## 5. BIM и браузерная часть

### Bonsai / IfcOpenShell

[IfcOpenShell](https://github.com/IfcOpenShell/IfcOpenShell) — open-source библиотека для IFC; README ветки v0.9.0 указывает поддержку чтения IFC2x3, IFC4 и IFC4x3 и экосистему инструментов. Bonsai — IFC-authoring add-on для Blender; в исходнике присутствуют модули систем, clash и IfcTester/IDS.

Лицензии различаются: IfcOpenShell core распространяется под LGPL; Bonsai — GPL-3.0-or-later. Это надо учитывать при распространении модифицированного программного обеспечения. IFC-модель и собственные данные A-01 можно вести отдельно от лицензии программы.

### ThatOpen Engine Components

[ThatOpen Engine Components](https://github.com/ThatOpen/engine_components) — актуальная библиотека для браузерных BIM-приложений на Three.js; в репозитории есть IFC loader, измерения площади/длины/углов, технические чертежи и примеры IDS. Лицензия MIT.

Для A-01 логичнее сначала сделать отдельную страницу/модуль просмотра IFC с измерениями, а не менять ядро v4.9.0. Старые репозитории web-ifc-viewer и web-ifc-three помечены deprecated; их README рекомендует использовать Components.

## 6. Предлагаемая схема применения к W-01

| Этап | Инструмент | Результат | Gate |
|---|---|---|---|
| 1. Калибровка | A-01 v4.9.0 + FreeCAD | Физический контрольный размер, затем реальный контур сектора D04 в мм | Масштаб модели подтверждён |
| 2. Геометрия | FreeCAD BIM + выборочные FCStd/STEP | Размерная оболочка, двери, перегородки, WC, раковины, трапы и зоны обслуживания | Все модели проверены в мм |
| 3. Fit-test | FreeCAD / отдельный браузерный тест | Проверка размещения приборов, дверей, маневрирования и сервисных зон | Нет геометрических конфликтов; проверка доступности отдельная |
| 4. MEP-проработка | openBIMstudio в отдельной песочнице | Эскиз труб, стояков, арматуры, вытяжки, сети и первичные сценарные расчёты | Все исходные данные отмечены; IPC-результаты не приняты как российские нормы |
| 5. BIM-паспорт | Bonsai / IfcOpenShell | IFC-пространство, IfcSanitaryTerminal, IfcPipeSegment, системы, Psets, GUID и координация | IFC читается повторно; IDs не теряются |
| 6. Проверка данных | IDS + геометрические тесты | Проверка наличия свойств и отдельных геометрических правил | IDS не подменяет проверку геометрии и нормативную экспертизу |
| 7. Веб-просмотр | ThatOpen Components | IFC-просмотр, сечения/измерения, видимость инженерных сетей | Изолированный модуль работает без изменения основного рендера A-01 |
| 8. Нормативная проверка | Российская матрица норм + профильные проектировщики | Отдельные расчёты по применимым СП и проектным условиям | Reviewed/approved только после профильной проверки |

## 7. Что необходимо сделать именно для D04

До начала расстановки оборудования нельзя использовать старую площадь 4,395 u² как площадь в квадратных метрах. Сначала требуется один измеренный контрольный размер для калибровки модели.

После калибровки построить D04 в миллиметрах и сравнить два сценария:

- **Сценарий W-01 внутри одного D04:** универсальное помещение, стандартная WC-зона, умывальники, вход/экран, уборочная и техническая часть. Это проверка вместимости, а не предположение, что всё поместится.
- **Составной санитарный кластер:** если fit-test не проходит, подготовить вариант с использованием соседних секторов и проверить, как он влияет на функции D03/D05 и маршруты L00. Перераспределение соседних секторов не считается принятым без отдельного решения.

Отдельно требуется найти/создать полноценные модели доступного WC, поручней, зон подхода и маневрирования. В найденных коллекциях наличие полного готового комплекта для универсальной доступной комнаты не подтверждено.

## 8. Правила использования внешнего кода и моделей

1. Не копировать Zamodelka и другие репозитории без явной лицензии/разрешения.
2. При использовании FreeCAD-library сохранять CC-BY 3.0 атрибуцию каждого автора/модели.
3. Сохранять MIT notices для openBIMstudio и ThatOpen, а для Bonsai соблюдать GPL-3.0-or-later и условия зависимостей.
4. Не смешивать чужую геометрию с утверждённым изделием: каждому семейству нужен статус placeholder, generic, manufacturer data, verified.
5. Не использовать зарубежные расчётные таблицы как российские нормативные значения.
6. Результат любого внешнего алгоритма хранить вместе с методом, стандартом, единицами, предпосылками, ограничениями и статусом проверки.

## 9. Предварительное решение по стеку

**Рекомендуется продолжить так:**
- взять FreeCAD/FreeCAD-library для первого размерного D04 и реальных STEP/FCStd-прототипов;
- открыть отдельную openBIMstudio-песочницу для изучения семейства приборов, MEP-трассировки и сценарных расчётов;
- назначить Bonsai/IfcOpenShell основным будущим IFC/BIM контуром A-01;
- использовать ThatOpen Components для будущего веб-просмотра IFC;
- Zamodelka оставить как исследовательский пример интерфейса, пока не выяснены права на код.

Это предварительная архитектура инструментария, не внедрение и не утверждение проектных решений. Основной цифровой двойник A-01 v4.9.0 пока не менялся.

**Статус W-01:** M0 / proposed / not calculated. Ни один внешний инструмент не подтвердил геометрическую вместимость, доступность или соответствие российским нормам.
