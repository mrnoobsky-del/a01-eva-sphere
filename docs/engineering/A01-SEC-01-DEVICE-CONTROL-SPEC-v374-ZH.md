# A-01 — A01-SEC-01：安全设备控制工程规范
**v3.7.4 文档包 · 简体中文 · 2026年11月21日**

> **状态：**工程需求与架构概念。本文件不是电气设计、采购规格、自动化施工设计，也不授权连接实际设备。真实电路、保护装置、布线、接触器、控制器及安装必须由具备资质的专业人员确定。

## 1. 目的与边界

建立统一界面，使穹顶居民和工作人员只能查看、控制明确获准的电子设备。手机不得成为直接远程控制建筑工程网络的入口。

基本命令路径：

**手机 / PWA → 身份验证访问网关 → 本地策略执行节点 → 分区控制器 → 开关执行装置 → 独立状态反馈。**

Eva 可以解释状态、帮助定位设备并准备请求，但不能超越用户权限、绕过联锁，也不能自行决定关闭安全保护系统。

第一阶段候选范围仅限指定的非关键负载：公共区域普通照明、信息显示屏、背景音响、经工程批准的特定维修插座组及用户充电点。这些是设计类别，不代表实体设备已经安装。

## 2. 设备分类与控制权限

| 类别 | 示例 | 远程控制 | 条件 |
|---|---|---|---|
| U1 — 个人设备 | 私人区域照明、个人界面设置 | 可以，在本人区域内 | 区域归属验证，保留本地手动控制 |
| U2 — 公共非关键设备 | 装饰照明、显示屏、背景音响 | 按角色允许 | 时间计划、限制；群组操作需确认 |
| U3 — 运维设备 | 服务插座、非关键工艺泵/风机 | 受限 | 仅受训人员；工作许可/维护模式；现场检查 |
| U4 — 关键工程设备 | 重要水泵、技术通风、服务器冷却 | 普通应用不可控制 | 独立自动化；可通过批准接口只读显示状态 |
| U5 — 生命安全/消防设备 | 火灾报警、应急照明、疏散通知、排烟、加压、防火阀、应急通信 | 不可控制 | 按项目设计采用独立系统和控制装置 |

每项实际负载必须由项目工程师和运营负责人分类。不得为了应用便利而降低设备的关键等级。

## 3. 角色与权限

- **访客：**仅查看公共信息，不可发送工程控制命令。
- **居民：**控制本人区域设备及获准的用户功能。
- **运营人员：**在指定班次/区域内控制有限的公共设备；所有命令记录日志。
- **工程师：**诊断和维护操作；危险操作须现场授权并进行物理确认。
- **安全管理员：**管理身份、角色、密钥、策略和会话撤销；无权绕过硬件保护。
- **服务身份：**独立机器身份，权限范围和有效期受限；禁止共享密码和永久令牌。

应用管理员不得通过软件关闭独立消防自动化或解除硬件联锁。

## 4. 命令生命周期

1. 用户选择设备和操作。
2. 应用显示设备名称、位置、关键等级和预期效果。
3. 网关验证身份、角色、设备绑定、会话有效期及具体命令权限。
4. 本地策略节点检查设备状态、联锁、时间计划、维护模式和冲突命令。
5. U3 需要现场工作人员确认；应用对 U4/U5 的控制命令必须拒绝。
6. 所有检查通过后，控制器才发出命令。
7. 独立反馈确认实际状态。
8. 界面区分“请求已接受”“命令已发送”“执行中”“传感器/触点已确认”“失败”及“状态未知”。
9. 日志记录操作者、设备、时间、结果和反馈来源。

命令成功发送不等于设备已实际切换。没有反馈或反馈矛盾时，必须显示“状态未知”，不得虚构成功状态。

## 5. 安全响应矩阵

| 事件 | 应用行为 | 本地系统行为 |
|---|---|---|
| 互联网/云服务中断 | 显示离线，停止远程命令 | 本地自动功能按设计继续 |
| 与控制器通信中断 | 不标记为完成 | 避免无限重试；进入该设备定义的安全状态 |
| 传感器与反馈不一致 | 显示冲突并报警 | 阻止危险动作并通知运营人员 |
| 会话过期/权限撤销 | 拒绝新命令 | 已发命令仅按本地逻辑和安全规则完成 |
| 数据包重放/延迟 | 拒绝过期请求 | 校验唯一 ID、有效期和防重放数据 |
| 急停 | 显示状态，不可解除联锁 | 停止和恢复遵循本地程序 |
| 维护状态 | 拒绝普通命令 | 现场隔离、防意外重启并由工作人员确认 |
| 火灾信号 | 仅通过批准通道通知 | 独立消防系统执行批准的因果逻辑 |

安全状态并非对所有负载都等于“关闭”：关闭泵、冷却、通风或保护功能本身可能造成危险。必须逐项通过风险分析确定。

## 6. 物理架构与接口

建议的逻辑组件：
- 具有受保护会话存储的移动客户端/PWA；
- 不允许互联网直接入站访问控制器的远程访问网关；
- 本地策略执行节点；
- 分段 OT 网络，以及独立的访客、居民、IoT 和运维网络区域；
- 根据真实需求和支持协议选型的控制器；
- 由电气设计确定的开关执行装置；
- 独立反馈，例如辅助触点、位置/电流传感器或其他适当方法；
- 本地控制面板和书面手动恢复程序；
- 具备防篡改保护并同步时间的事件日志。

在完成负载清单、电流计算、环境评估和网络安全风险审查前，不确定具体协议、控制器型号或接触器。

## 7. 安全与隐私要求

- 特权角色使用 MFA 或 passkey；支持设备绑定和撤销。
- 最小权限、个人身份、短时令牌。
- 命令签名、唯一 nonce/ID、有效期、防重放和频率限制。
- 加密通信及密钥生命周期保护。
- 网络分段；控制器不得直接暴露在公共互联网。
- 签名更新、版本清单和回滚计划。
- 记录访问与操作，不收集不必要的个人数据。
- 麦克风/摄像头功能必须明确征得同意并提供可见提示；禁止隐蔽监控。
- 明确遥测数据的保存、删除和访问规则。
- Eva 不得根据推测的意图发出设备命令；必须有明确用户请求并通过权限检查。

## 8. 手机界面要求

必须显示以下状态：
- 可用 / 当前角色无权限；
- 在线 / 离线；
- 请求已发送 / 等待确认 / 已确认 / 失败 / 未知；
- 被本地自动化锁定；
- 需要现场专业人员；
- 维护中 — 控制不可用。

危险操作和群组操作必须明确列出受影响设备并要求确认。不得提供一个“关闭全部”按钮。显示设备关键等级、位置和拒绝原因。支持键盘和屏幕阅读器。

## 9. 设备最小数据模型

每个可控设备必须包含：
- 不可变的唯一 ID；
- 名称、类型、区域及运维负责人；
- U1–U5 关键等级及理由；
- 允许的命令和角色；
- 模式：normal / maintenance / locked / fault；
- 实际状态反馈来源及最后确认时间；
- 允许的时间窗口和限制；
- 安全状态及手动恢复程序；
- 与供电回路、控制器和保护系统的关联；
- 配置变更和版本历史。

## 10. 实施阶段与验收条件

**S0 — 资产清单：**负载、用途、区域、电流/功率、关键等级、电源和负责人。

**S1 — 风险分析：**OT/IT 威胁、错误命令后果、断电/断网、自动化与手动控制冲突。

**S2 — 无负载测试台：**使用模拟器测试角色、签名命令、防重放、会话撤销、日志和反馈。

**S3 — 单个 U2 组样机：**在低压/隔离测试台上验证；真实电气负载须另行批准设计。

**S4 — 试点：**只有在电气设计、保护装置图、本地控制、风险审查和运行程序获批后才能进行。

**S5 — 扩展：**每新增一组设备都必须重新分类和测试；一个设备的批准不自动适用于其他设备。

验收要求：拒绝禁止命令；权限可撤销；阻止重放和过期命令；无反馈时不得显示为已确认；云服务中断不影响本地保护；手动控制与恢复经过测试；日志能够还原事件顺序。

## 11. 尚待确定事项

实体控制器、协议、电压、额定值、保护装置、网络拓扑、IAM 提供商、数据保存策略和具体设备均未选定。不能仅凭视觉原型采购设备。仍需场地数据、负载清单、计算、适用规范、电气/OT/网络安全专家及测试。
