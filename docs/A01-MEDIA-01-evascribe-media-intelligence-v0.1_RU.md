# A01-MEDIA-01 — EvaScribe: медиатека, транскрибация и видеоисследования

**Редакция:** 0.1  
**Дата:** 25 ноября 2026 года  
**Статус:** концепция продукта и техническое задание на MVP; программная реализация ещё не начата.  
**Рабочее имя:** EvaScribe  
**Назначение:** единый инструмент для изучения видео, аудио, лекций, интервью, демонстраций, подкастов и материалов проекта A-01/VibeShorts.

> EvaScribe — наш собственный инструмент, вдохновлённый возможностями VidScribe и смежных открытых проектов. Это не копия стороннего продукта и не переименование чужого кода. Использование сторонних библиотек допускается только с проверкой лицензии и сохранением атрибуции.

## 1. Идея

**Превратить видео из пассивного просмотра в материал, который можно искать, проверять, цитировать по времени, сравнивать и превращать в знания.**

Пользователь добавляет ссылку или файл. Система определяет источник, находит готовые субтитры, если они доступны, или создаёт расшифровку. Затем формирует краткий обзор, главы, ключевые темы, факты, вопросы, задачи и ссылочные таймкоды. Для видео дополнительно извлекаются репрезентативные кадры и, при необходимости, надписи на экране.

Главный результат — не просто текстовый файл, а **карточка источника с проверяемой привязкой каждого важного вывода к исходному моменту видео**.

## 2. Что это откроет для наших проектов

### A-01 / Сфера Евы
- Изучать видеотуры по зданиям, инженерным системам, планетариям, куполам, промышленным объектам и подземной инфраструктуре.
- Быстро находить в лекции или презентации точный момент, где обсуждается технология, устройство, материал или ограничение.
- Сопоставлять несколько видео и выделять совпадения и противоречия.
- Создавать исследовательскую записку со ссылкой на видео и таймкод, а затем вручную сверять утверждения с официальной документацией и стандартами.
- Извлекать структуру лекции, список терминов, вопросы к эксперту и темы для дальнейшего изучения.

### VibeShorts
- Делать черновики заголовков, описаний, тематических подборок и субтитров из разрешённых пользователем материалов.
- Находить потенциальные фрагменты для коротких роликов по теме и таймкодам.
- Экспортировать SRT/VTT и текстовые заготовки.
- Собирать собственную медиатеку идей и источников, не публикуя ничего автоматически.

### Eva / Orion
- Задавать Еве вопросы по собственной медиатеке и получать ответ с названием источника, таймкодом и ссылкой на оригинал.
- Сохранять конспект в Notion или проектную документацию после подтверждения человеком.
- Преобразовывать пункты «что проверить / что сделать» в черновики задач Orion.
- Использовать один и тот же инструмент для A-01, VibeShorts и личной исследовательской медиатеки, разделяя рабочие пространства и права доступа.

## 3. Сценарий пользователя

1. Нажать «Добавить материал».
2. Вставить URL или выбрать локальный аудио-/видеофайл.
3. Система показывает метаданные и найденные субтитры.
4. Пользователь выбирает режим: только расшифровка, анализ, визуальные кадры или полный разбор.
5. Задача попадает в очередь: получение разрешённого источника → извлечение аудио → транскрибация → анализ → сохранение.
6. Открывается страница материала: плеер, кликабельный транскрипт, главы, краткое содержание и вопросы.
7. Пользователь задаёт вопрос по ролику. Ответ содержит таймкод и ссылку на источник.
8. Материал сохраняется в библиотеку и становится доступным для полнотекстового поиска.

## 5. Интерфейс

Предлагается рабочее пространство из трёх зон:

- **Слева — библиотека:** проекты, папки, недавние материалы, фильтры и очередь.
- **В центре — материал:** плеер, временная шкала, главы, ключевые кадры и синхронизированный транскрипт. Нажатие на таймкод перемещает видео к нужному месту.
- **Справа — интеллектуальная панель:** краткий обзор, факты, вопросы, сравнение источников, задачи и заметки.

Основные состояния задачи: queued → inspecting → captions_found / extracting_audio → transcribing → analyzing → ready; также paused, needs_attention, failed, cancelled.

Для каждого шага показываются прогресс, выбранный движок и понятная ошибка. Повторный запуск не должен повторно обрабатывать уже готовые результаты без запроса пользователя.

## 6. Техническое предложение

### 6.1 Первый вариант — локально на Windows

Основной целевой сценарий — запуск на обычном компьютере пользователя, с открытием интерфейса в браузере по адресу localhost. Это позволяет начать без аренды сервера и не отправлять личные видео в облако по умолчанию.

Предлагаемый стек:

- **Frontend:** React/Next.js, адаптивная тёмная/светлая библиотека и рабочая панель.
- **Backend:** Python 3.11+ и FastAPI.
- **Медиа:** FFmpeg для аудио, контейнеров и кадров.
- **Получение публичных источников:** yt-dlp как опциональный адаптер, только для разрешённых источников и сценариев.
- **Распознавание:** faster-whisper по умолчанию; whisper.cpp как дополнительный переносимый/CPU-ориентированный движок.
- **Слова и говорящие:** WhisperX как дополнительный режим, если потребуется точное выравнивание слов и diarization.
- **AI-анализ:** интерфейс провайдеров, совместимый с локальной моделью Ollama и выбранным OpenAI-compatible endpoint; внешняя обработка включается явно.
- **Хранилище:** SQLite + FTS5 на первом этапе; файлы транскриптов, JSON и Markdown хранятся в структуре каталога пользователя.
- **Очередь:** один локальный worker в MVP с очередью, возобновлением, отменой и retry.
- **Интеграции:** REST API и позднее MCP-сервер для Евы/Orion.

### 6.2 Разделение вычислений

Статический хостинг Wix или GitHub Pages не предназначен для запуска FFmpeg и Whisper. Поэтому публичный лендинг может объяснять продукт и открывать интерфейс, но обработчик медиа должен работать отдельно — сначала на локальном ПК, позже при необходимости на собственном сервере.

Cloudflare Worker можно использовать как лёгкий слой маршрутизации, уведомлений и авторизации, но не следует пытаться выполнять длительную транскрибацию больших видео внутри обычного Worker.

### 6.3 Нормализованная модель данных

**MediaSource**
- source_id, URL, title, creator, published_at, duration, source_type, workspace_id, rights_status, created_at.

**MediaAsset**
- asset_id, source_id, local_path, mime_type, file_size, checksum, retention_policy.

**TranscriptSegment**
- segment_id, source_id, start_ms, end_ms, text, speaker_id, confidence, engine, language.

**Speaker**
- speaker_id, source_id, label, optional_description. Не пытаться определять личность человека только по голосу.

**Analysis**
- summary, chapters, topics, claims, uncertainties, action_items, model_id, prompt_version, created_at.

**Frame**
- frame_id, source_id, timestamp_ms, local_path, optional_ocr_text.

**EvidenceLink**
- analysis_item_id, source_id, start_ms, end_ms, evidence_type. Каждый существенный тезис должен иметь привязку к источнику.

**Job**
- job_id, source_id, stage, progress, state, retry_count, error_code, started_at, finished_at.

## 7. Принципы качества и достоверности

- Отделять «в видео говорится» от «это независимо подтверждено».
- Не выдавать вывод модели за факт.
- Для каждого ключевого тезиса показывать источник и временной диапазон.
- Сохранять оригинальный язык и отдельный перевод, не заменяя один другим.
- Указывать выбранную ASR-модель и её версию.
- Показывать, где автоматическое распознавание не уверено, а где отсутствует звук.
- Не делать OCR или извлечение кадров обязательным для каждого ролика: включать по сценарию, чтобы экономить время и место.
- Не путать speaker labels с установленной личностью человека.
- В исследовательских отчётах формировать список непроверенных утверждений и документов, которые нужно найти независимо.

## 8. Приватность, безопасность и права

- По умолчанию локальная обработка; облачный AI — только по явному выбору.
- Секреты и API-ключи — только в локальном хранилище конфигурации/переменных окружения, никогда не в GitHub и не во frontend.
- Веб-интерфейс локального MVP привязывается к loopback (127.0.0.1), а не открыт в интернет.
- Импорт URL защищается от SSRF: блокируются localhost, private/reserved IP, внутренние домены и неожиданные протоколы. Нельзя превращать ссылку на видео в универсальный прокси доступа к внутренней сети.
- Ограничить размер, длительность и тип файла, очистку временных данных, хранение и удаление материалов.
- Не обходить DRM, paywall, авторизацию, технические ограничения платформы и не использовать чужие закрытые сессии.
- Обрабатывать только материалы пользователя, материалы с разрешением или источники в рамках применимых прав и условий сервиса.
- Не публиковать автоматически полученные фрагменты; подготовка контента заканчивается черновиком и ручной проверкой прав/контекста.
- Не выводить большие фрагменты защищённого текста как публичный заменитель оригинала; в публичных материалах использовать краткое изложение, необходимые короткие выдержки и ссылку на первоисточник.

## 10. План разработки

### MVP / v0.1
- Локальный запуск в Windows.
- Добавление одного файла или одного URL за раз.
- Сначала доступные субтитры; затем локальный faster-whisper.
- Синхронизированные таймкоды и плеер.
- Краткое содержание и главы.
- Поиск по локальной библиотеке через SQLite FTS5.
- Экспорт TXT, MD, JSON, SRT, VTT.
- Понятная очередь, журнал ошибки, повтор/отмена.
- Никаких аккаунтов, публичного доступа, платежей и автоматической публикации.

### v0.2 / Исследовательский режим
- Вопросы к одному источнику и к библиотеке.
- Ответы с таймкодами и прямыми ссылками на исходный ролик.
- Сравнение нескольких роликов.
- Шаблон «техническая исследовательская записка A-01».
- Экспорт в Markdown для GitHub/Notion.

### v0.3 / Визуальный разбор
- Извлечение сцен и ключевых кадров.
- OCR для презентаций, схем и экранных надписей.
- Дополнительная диаризация.
- Галерея кадров и переход по таймкодам.

### v0.4 / Библиотека и автоматизация
- Импорт каналов и плейлистов с лимитами.
- Повторная обработка только новых/ошибочных материалов.
- MCP-интерфейс для Евы.
- API и вебхуки для Orion.

### v0.5 / VibeShorts Studio
- Черновики коротких роликов с таймкодами.
- Варианты названия, описания и субтитров.
- Экспорт редакторских пакетов.
- Только ручное подтверждение перед публикацией.

## 11. Критерии готовности MVP

- Локальный файл можно обработать без отправки медиа наружу.
- Для одного материала создана запись, транскрипт и таймкоды.
- Нажатие на сегмент открывает соответствующий момент видео.
- Поиск находит слово/фразу в нескольких сохранённых материалах.
- Экспорт SRT и VTT проверяется на временную структуру.
- Неудачная задача может быть повторена без дублирования записи.
- Удаление материала очищает связанные временные файлы согласно выбранной политике.
- В логах нет API-ключей, паролей или приватных URL.
- В README описаны установка, запуск и деинсталляция для Windows.
- Ни один AI-вывод не показывается без ссылки на источник и таймкод, когда это применимо.

## 12. Открытые решения перед кодированием

1. Подтвердить рабочее имя EvaScribe и расположение исходников: отдельный репозиторий или папка `tools/eva-scribe/` в A-01.
2. Выбрать минимальный ASR-профиль для компьютера пользователя: CPU или NVIDIA GPU; неизвестные характеристики не подменять предположениями.
3. Решить, какие источники URL разрешены на MVP; по умолчанию поддержать локальные файлы и YouTube URL, если доступ и обработка соответствуют правилам источника.
4. Определить место хранения локальной медиатеки и резервных копий.
5. Выбрать один локальный/облачный провайдер для кратких конспектов; ключи не добавлять в исходный код.

**Рекомендация по старту:** сделать Windows-first локальный MVP. Сначала добиться надёжного контура «файл/разрешённый URL → субтитры или Whisper → точный транскрипт → поиск → краткий конспект с таймкодами». Только после этого наращивать OCR, диаризацию, пакетную обработку, облачную интеграцию Евы и VibeShorts Studio.
