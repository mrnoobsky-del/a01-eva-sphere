# A-01 v3.3.0 — Архитектура автономной цифровой Сферы Евы

**Статус:** архитектурная спецификация и план реализации. Это не утверждение о готовой автономной сборке и не подтверждение прохождения offline-приёмки.

## Цель

Сделать цифровой двойник A-01 работоспособным при полном отсутствии внешней сети. Интернет должен расширять возможности проекта, но не быть условием запуска 3D-сцены, навигации, просмотра объектов и локальных материалов.

Главный пользовательский сценарий: пользователь отключает сеть, дважды щёлкает по одному HTML-файлу, открывает цифровую Сферу Евы, осматривает модель, перемещается, изучает объекты, использует локальную справку и сохраняет доступные локальные данные.

## Цели автономного ядра

1. Запуск из file:// без локального сервера, BAT-файлов, CDN и внешних JavaScript-модулей.
2. Сохранение текущей 3D-сцены, управления камерой, навигации, адаптивного интерфейса и режима изучения объектов.
3. Доступ к локальной документации, описаниям объектов, схемам и включённым ресурсам.
4. Предсказуемая работа без сети с понятным индикатором Offline.
5. Явное отделение локальных данных от сетевой синхронизации и серверных функций.
6. Проверяемая сборка с манифестом ресурсов, лицензиями и отчётом тестирования.

## Слои архитектуры

### A-01 CORE

Локальный runtime, интерфейс, 3D-движок, камера и управление, реестр объектов, локальная модель данных, справка, настройки и диагностика.

### World Runtime

Модули человечка, движения, взаимодействия с объектами, локальной логики Евы и других доступных агентов. Модуль должен иметь явный контракт запуска и graceful-degradation: отсутствие необязательного агента не должно ломать базовую сцену.

### Local Knowledge

Встроенные описания объектов, уровней, инженерных подсистем, инструкции, справочники и локальная полнотекстовая/структурная навигация. Внешние ссылки маркируются как недоступные без сети; локальные копии документов включаются только при наличии прав и актуальной версии.

### Local Data

Настройки, локальные заметки, выбранные объекты, локальные задачи и экспортируемые снимки состояния. Для file:// нельзя полагаться на одинаковое поведение localStorage/IndexedDB во всех браузерах. Поэтому слой хранения обязан проверять доступность API, показывать статус сохранения и предоставлять экспорт/импорт JSON. Нельзя показывать «сохранено», если запись не подтверждена.

### Online Adapter

Отдельный сетевой адаптер для Cloudflare Worker/Евы, синхронизации, обновлений и внешних сервисов. Каждая сетевая функция должна иметь тайм-аут, обработку ошибок и автономный fallback. По умолчанию локальные данные не отправляются на сервер без явного действия пользователя.

### Optional Local AI

Отдельный необязательный модуль для языковой модели, работающей на устройстве. Это не часть минимального HTML-ядра: модели требуют отдельных весов, вычислительных ресурсов и runtime. В базовом Offline-режиме доступна локальная справка и заранее определённые локальные функции, но не имитируется полноценная облачная LLM.

## Стратегия поставки

### 1. Single HTML Offline

Основной целевой сценарий. На этапе сборки исходные ES-модули, включая Three.js и необходимые контролы, собираются в единый самодостаточный JavaScript bundle без внешних import-зависимостей. Bundle встраивается в HTML. Статические ресурсы либо встраиваются в HTML как data URL/встроенные данные, либо создаются процедурно. Любые оставшиеся внешние файлы должны быть выявлены сборочной проверкой.

Не следует считать простое добавление CDN import map или относительного пути к vendor-папке автономной сборкой. Для проверки результата не допускается ни один обязательный сетевой запрос.

### 2. Portable Offline Pack

Отдельный архив с HTML, локальными библиотеками, медиа-ресурсами, документацией, лицензиями, манифестом и проверяющим запускателем. Если браузерная политика или объём ресурсов делают двойной щелчок ненадёжным, пакет может предлагать локальный сервер как альтернативный способ запуска. Этот сценарий не заменяет Single HTML acceptance.

### 3. PWA / Hosted Offline

Отдельная HTTPS-версия с Service Worker и кэшированием. Service Worker относится к опубликованному origin и не является механизмом запуска HTML из file://. PWA — дополнительный канал поставки, а не замена автономному файлу.

## Требования к модульности

- Встроенный runtime не должен выполнять сетевые импорты.
- Все используемые версии библиотек фиксируются; лицензии и notices поставляются вместе с пакетом.
- Сборка должна проверять все script/module src, CSS url(), загрузчики текстур, модели, шрифты, аудио, fetch(), WebSocket и динамические импорты.
- Внешние источники могут использоваться только как необязательные функции и не должны блокировать старт.
- Отсутствие WebGL должно приводить к понятному диагностическому экрану, а не сообщению о недоступности CDN.
- Ошибка одного необязательного модуля не должна останавливать основной интерфейс.
- Нужны version manifest, SHA-256 для сборочных ресурсов и отчёт о лицензиях.

## Сетевые и локальные режимы

| Функция | Offline | Online |
|---|---|---|
| 3D-сцена и камера | Да | Да |
| Навигация и изучение объектов | Да | Да |
| Встроенная база знаний | Да | Да |
| Локальные настройки и экспорт | Да, с проверкой хранилища | Да |
| Чат с серверной Евой | Нет | Да |
| Синхронизация с сервером | Нет; очередь изменений локальна | По согласию пользователя |
| Локальная LLM | Только при отдельной установке | Опционально |
| Внешние ссылки и сервисы | Нет | Да |

## Сохранение и синхронизация

1. При старте выполнить проверку localStorage, IndexedDB и доступности записи/чтения.
2. Показать реальный статус: «сохранение доступно», «только экспорт» или «хранилище недоступно».
3. Предоставить экспорт JSON и импорт с проверкой схемы и версии.
4. Сетевую синхронизацию делать отдельным пользовательским действием.
5. Перед миграцией или синхронизацией создавать резервную копию.
6. Конфликты не перезаписывать молча: показать выбор или сохранить обе версии.

## Безопасность

- Не встраивать секреты, API-ключи и приватные токены в HTML.
- Не отправлять локальные заметки, историю и задачи автоматически.
- Внешние команды и ссылки явно помечать как сетевые.
- Проверять импортируемые JSON по схеме, размеру и допустимым полям.
- Для локальных ресурсов предпочитать проверенные и фиксированные сборочные артефакты.
- Поставлять Third-party Notices и исходные лицензии.

## План реализации

**Этап 0 — Baseline:** зафиксировать исходную версию, перечень всех импортов/ресурсов, текущие функции, размеры и контрольные хэши.

**Этап 1 — Dependency audit:** просканировать HTML, CSS и JavaScript на внешние источники: import/import(), src/href, url(), fetch, XHR, WebSocket, Worker, шрифты, изображения, модели, аудио и видео.

**Этап 2 — Bundle:** создать воспроизводимый build pipeline с закреплёнными версиями инструментов и библиотек; получить самодостаточный bundle без runtime-импортов.

**Этап 3 — Asset packaging:** встроить обязательные ресурсы, проверить загрузчики и удалить блокирующие обращения к сети.

**Этап 4 — Local data:** добавить capability probe, статусы сохранения, JSON export/import и версионирование схемы.

**Этап 5 — Network isolation:** перевести серверные функции на Online Adapter и проверить graceful-degradation в режиме Offline.

**Этап 6 — Acceptance:** провести browser-тесты на реальном Chromium/Edge и Firefox, включая первый запуск после отключения сети и чистый профиль.

**Этап 7 — Portable/PWA:** собрать второй архив и отдельно описать PWA/HTTPS deployment.

## Критерии приёмки Single HTML

- HTML открывается двойным щелчком при заранее отключённой сети.
- В DevTools Network нет обязательных HTTP(S)-запросов; любые попытки сетевых функций блокируются либо явно помечаются как optional.
- 3D-сцена отрисовывается и не показывает ошибку «не удалось загрузить 3D-движок».
- Работают камера, навигация, выбор уровня, изучение объектов и возврат к интерфейсу.
- Раскрытие бокового меню сужает центральную область, а не накрывает её на десктопе.
- Нет ошибок JS, связанных с незагруженными модулями или ресурсами.
- Проверены WebGL и поведение при его недоступности.
- Сохранение проверено закрытием и повторным открытием; если браузер не предоставляет устойчивое хранилище, UI предлагает экспорт.
- Архив/HTML содержит версию, SHA-256, список библиотек и лицензий.
- Результаты acceptance записаны с браузером, ОС, датой и фактическими сетевыми логами.

## Матрица тестирования

Проверять минимум:
- Chromium/Chrome и Edge на Windows;
- Firefox на Windows;
- Chromium на Linux;
- актуальные настольные браузеры macOS;
- мобильный Safari/Chrome — отдельно, поскольку открытие локального HTML и файловое хранилище имеют дополнительные ограничения.

Каждый отчёт должен различать: **PASS**, **FAIL**, **NOT TESTED**. Статическая проверка кода не считается подтверждением визуального браузерного запуска.

## Текущий статус v3.3.0

- Архитектура и требования описаны.
- Полная автономная сборка ещё не подтверждена.
- Текущая v3.2.2 остаётся онлайн-зависимым вариантом с CDN.
- Предыдущий local-engine ZIP нельзя считать готовым offline build без проверки наличия всех библиотек и ресурсов в архиве.
- uCoz deployment не входит в эту задачу и не выполняется автоматически.
