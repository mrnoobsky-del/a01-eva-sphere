# A-01 v4.x — слой производительности 60 FPS

Этот модуль добавляет диагностику Three.js-сцены и консервативное адаптивное управление разрешением. Он не подменяет Three.js и не требует сторонней библиотеки.

## Подключение

Вставить обычный script-тег после основного `<script type="module">` цифрового двойника, который создаёт `window.EVA_SPHERE`:

```html
<script src="./performance/a01-performance-layer.js"></script>
```

Поскольку основной модуль Three.js использует отложенное выполнение, этот обычный скрипт успевает зарегистрировать событие `eva-a01:scene-ready`. Сам файл должен находиться рядом с HTML в папке `performance`. Для полностью автономного одиночного HTML содержимое скрипта можно встроить непосредственно перед `evaA01UnifiedWorkspace`.

## Возможности

- Кнопка «A-01 · FPS» появляется в нижней правой части 3D-сцены.
- F3 открывает и скрывает диагностическую панель.
- Показываются FPS, средний интервал кадра, p95, CPU-время вызова `renderer.render()`, draw calls, треугольники, число геометрий и текстур, текущий pixel ratio.
- Адаптивное качество по умолчанию включено. При устойчивом FPS ниже 54 два контрольных окна подряд разрешение постепенно уменьшается; после четырёх контрольных окон выше 58,5 оно осторожно восстанавливается.
- «Сброс качества» возвращает исходный pixel ratio.
- API доступен через `window.A01Performance` и `window.EVA_SPHERE.performance`.

## Важные границы

1. FPS считается по реальным вызовам `renderer.render()`; синтетические кадры Frame Generation не учитываются.
2. CPU-время вызова рендера не является измерением GPU-времени. Для глубокого GPU-профилирования используйте Nsight Systems/Graphics и внешнюю телеметрию.
3. Модуль не обещает 60 FPS на любом устройстве. Это цель приёмки на согласованной эталонной конфигурации.
4. Мобильные устройства получают более низкий минимальный pixel ratio, но сохраняют тот же алгоритм измерения.
5. Модуль не меняет геометрию, материалы, камеру, освещение, пользовательские маршруты или логику исследования объектов.

## Связанные оптимизации

В интегрированной сборке A-01 v4.0.2 повторяющиеся 12 радиальных элементов каждого уровня собраны в один `THREE.InstancedMesh` на этаж. Пять групп вместо 60 отдельных Mesh уменьшают число draw calls. Применять этот паттерн к другим объектам следует только после проверки, что они не анимируются и не имеют собственной логики выбора.

Для дальнейших GLB-ассетов отдельно рассматриваются glTF Transform, meshoptimizer и KTX2. Для текущей процедурной геометрии эти инструменты не являются обязательными runtime-зависимостями.

## Проверка

- `node --check digital-twin/performance/a01-performance-layer.js`
- Открыть цифровой двойник в браузере и включить панель через F3.
- Пройти 10 минут по L00–L04, проверить двери, робота, выбор объектов, переключение этажей и режим осмотра.
- Отдельно измерить на референсном ПК при 1920×1080 и записать GPU/CPU, браузер, драйвер, средний FPS и p95.
- Не объявлять цель 60 FPS достигнутой до фактического браузерного прогона.

**Совместимость:** рассчитан на A-01 v4.x с Three.js 0.185.0 и API `window.EVA_SPHERE`. Для старых сборок требуется отдельно проверить наличие события `eva-a01:scene-ready`.

# A-01 — протокол приёмки 60 FPS

## Эталонный ПК

Перед измерением зафиксировать модель CPU, GPU, объём RAM/VRAM, браузер, ОС, разрешение экрана, частоту обновления, версию драйвера и режим питания.

## Сценарии

1. Неподвижный обзор купола.
2. Плавный полный оборот камеры.
3. Прогулка по L00, затем переходы на L01–L04.
4. Открытие/закрытие дверей и интерактивных объектов.
5. Запуск анимации обслуживания дольки и сервисной кассеты.
6. Исследование объекта с открытой карточкой.
7. Возврат к общему обзору.
8. Десятиминутный непрерывный тест для выявления нагрева и троттлинга.

## Критерии

| Метрика | Цель |
|---|---:|
| Реальные render calls | не менее 60 FPS на эталонном дисплее 60 Hz |
| Бюджет кадра | 16,67 мс |
| p95 интервала кадра | ≤16,67 мс |
| Долгий прогон | 10 минут без деградации |
| Визуальные регрессии | 0 критических |
| Потеря функций/селекции | 0 |

На мониторе с частотой выше 60 Hz отчёт показывает фактическую частоту render calls; для сравнимости отдельно отметить герцовку дисплея. Frame Generation не засчитывается в FPS приёмки.

## Ограничения измерителя

Панель A-01 измеряет интервалы между вызовами `renderer.render()`, CPU-время этой функции и данные `renderer.info`. Это не полноценное измерение GPU execution time. Для GPU-трассировки использовать NVIDIA Nsight Systems/Graphics. RTX Lens пригоден для наблюдения за температурой, частотами и энергопотреблением, но не подменяет профилировщик кадров.
