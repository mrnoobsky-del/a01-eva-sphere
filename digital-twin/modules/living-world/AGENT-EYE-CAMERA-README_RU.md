# A-01 AgentEyeCamera v0.1 — камера от первого лица

**Ветка:** feature/a01-agent-eye-camera-v0.1  
**Основа:** экспериментальный feature/living-world-v0.1 с интерфейсом window.EVA_SPHERE.  
**Статус:** программный адаптер и тестовый стенд; привязка к реальному Android-01 ещё не выполнена.

## Что реализовано

- Отдельная THREE.PerspectiveCamera, дочерняя реальному THREE.Object3D / Bone головы.
- Отдельный canvas и второй THREE.WebGLRenderer: основная камера наблюдателя, OrbitControls и основной renderer не подменяются.
- Локальный видеопоток через HTMLCanvasElement.captureStream() с ограничением до 15 FPS; исходное значение по умолчанию — 6 FPS.
- Получение локального кадра через captureFrame() с Blob и временными метаданными.
- Ручной запуск с отдельным временным разрешением; без разрешения поток не включается.
- Автоматическое подключение по событию a01-agent:head-ready, когда runtime передаёт настоящий объект головы.
- Остановка треков, истечение разрешения, обработка ошибки WebGL и удаление камеры из rig.

## Важное ограничение текущей интеграции

В доступной ветке Living World есть общий Three.js scene API window.EVA_SPHERE, муха-спутник и световой orb. В опубликованном исходнике этой ветки не найдено подтверждённого гуманоидного rig Android-01 и стабильного публичного объекта его головы. Поэтому адаптер не присоединяется к мухе, орбу или произвольно выбранному объекту сцены.

agent-eye-camera-preview.html содержит отдельный процедурный гуманоидный тестовый rig. Он нужен для проверки камеры, крепления к голове, поворотов и независимости от spectator camera. Это тестовый манекен, а не модель Android-01 и не замена его исходному runtime.

Для прямой интеграции в настоящий Android-01 его загрузчик должен после создания головы отправить событие a01-agent:head-ready с действительным THREE.Object3D / Bone. Необходимо также проверить направление взгляда и калибровку mount transform на фактической модели.

## Подключение

1. Загрузить agent-eye-camera.js до того, как humanoid runtime отправит событие готовности головы.
2. После создания Android rig отправить a01-agent:head-ready, передав agentId, headObject и API сцены.
3. По явному действию оператора вызвать A01_AGENT_EYE_CAMERA.start() с краткосрочным разрешением local_eye_stream.
4. Локальный поток можно показать в HTML video или передать локальному инспектору. Модуль сам ничего не отправляет в сеть.
5. Для кадра вызвать captureFrame(); он вернёт Blob и метаданные. Загрузка кадра в endpoint не реализована.
6. По завершении вызвать stop(); для полного удаления камеры и обработчика события — detach() или destroy().

Пример вызова находится в agent-eye-camera-integration.html.

## Публичный API

- attach({agentId, headObject, api, options})
- start({authorization, videoElement})
- stop()
- captureFrame()
- getStream()
- getStatus()
- detach()
- destroy()

События окна: a01-agent-eye:ready, streaming, frame, stopped, permission-expired, preview-blocked, error.

Разрешение должно содержать уникальный authorizationId, grantedBy, grantedAt, expiresAt в будущем и scope: ["local_eye_stream"]. Разрешение автоматически прекращается по времени. Этот модуль реализует только локальный поток. Права на внешнюю передачу и хранение здесь не выдаются.

## Проверки

Из корня репозитория:

    node --check digital-twin/modules/living-world/agent-eye-camera.js
    node --test digital-twin/modules/living-world/tests/agent-eye-camera.test.cjs

Тесты используют mock Three.js и browser APIs. Они проверяют крепление камеры, отдельность основной камеры, запрет старта без разрешения, кадровый цикл, локальный Blob, остановку tracks и автоматическое присоединение по событию. Это не заменяет браузерный WebGL-тест.

Откройте agent-eye-camera-preview.html в браузере с доступом к CDN Three.js для ручной проверки картинки. Нажмите «Включить локальный поток» — это включает только локальный canvas stream в текущей вкладке. Поворачивайте голову ползунками: глазной ракурс меняется, spectator camera остаётся независимой.

## Ограничения и безопасность

- Нет камеры физического устройства, микрофона, сети, внешней модели или ROS 2 драйвера.
- Не выполнена отправка кадров в vision model или Sensory Bridge endpoint.
- Модуль не управляет суставами и не выдаёт команд роботу.
- Примерный humanoid rig — только fixture для тестирования.
- Отдельный WebGLRenderer создаёт дополнительный графический контекст; для слабых мобильных GPU необходимо проверить расход памяти и частоту кадров.
- Для физического Android-01 нужны аппаратный camera driver, калибровка, secure media gateway, аудит и отдельная safety review.
- При потере сети этот локальный модуль не должен становиться частью safety-critical контура.
