# Android-01 для основной сцены A-01

Каталог `agent/mainline/` содержит модули интеграции Agent Runtime в основную сцену Сферы Евы из опубликованной линии v3.1.6.

- `agent-runtime.js` — план миссии, allowlist инструментов, явная авторизация, отмена, журнал и проверка результата.
- `agent-eye-camera.js` — локальная камера на кости головы Android-01; сама по себе не отправляет кадры в сеть.
- `agent-android-rig.js` — процедурный скелет Android-01.
- `mainline-scene-adapter.js` — связывает персонажа и Runtime с существующими `window.EVA_SPHERE`, уровнями и объектами.

Адаптер строит временный маршрутный граф по пяти уровням. 24 точки галереи на уровень и три межуровневых соединения — условная топология, а не фактический план лифтов или навигации. Точные физические координаты и проходимость не подтверждены.

Runtime не получает доступа к произвольному JS, строительным системам или физическим исполнительным устройствам. Изменяющие состояние действия требуют явного подтверждения через UI. Это не полноценная граница безопасности от намеренной модификации локальной страницы и не сертифицированный останов физического робота.

Sensory Bridge, MCP и HTTP API из X не включены в основную веб-сборку. Внешняя модель-планировщик не подключена. Камера и движение симуляционные.

Проверка: `node tests/mainline-agent-adapter-check.mjs`.


## Геометрические ограничения v3.1.8

- Центр кольцевого прохода: радиус 4.72 условной единицы. Для агента принят горизонтальный радиальный габарит ±0.18; тело занимает диапазон 4.54–4.90.
- Дверные рамы расположены на радиусе 4.98. Маркеры подхода к существующим лестничным проёмам — на радиусе 5.15 и совмещены с осями 90°/270°; сами существующие лестничные марши начинаются около радиуса 5.40. Дублирующие лестничные объекты не создаются. Проверены зазоры между оболочкой агента, дверями, маркерами и краем марша.
- Путь к жилому/общественному объекту заканчивается у внутреннего порога, а не внутри помещения. Сервисные доли, B1, наружные кассеты и LED-панели не являются целями для ходьбы.
- Это статический граф и аналитическая оболочка маршрута, а не полноценный navmesh/physics solver. Свободная камера «Исследование» на странице остаётся отдельным режимом полёта без collision solver.


## Режим изучения объектов v3.1.9

Кнопка «Изучить объект» открывает полноэкранный режим основной сцены: камера фокусируется на объекте, интерфейс временно скрывается, карточка объекта остаётся поверх модели. Крестик или Escape закрывают карточку и восстанавливают прежний интерфейс, включая открытую до просмотра контекстную панель. На время просмотра заблокированы выбор других объектов на canvas и ввод перемещения; после закрытия доступ к модели возвращается.

Проверка: `node tests/object-study-mode-check.mjs`. Полный браузерный/WebGL walkthrough в этой среде не завершён.
